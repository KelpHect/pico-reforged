title: CSS variables
description: Every color, size and spacing is a --pico-* custom property. Override one in your own CSS, on the page or on a single element.
---

Pico Reforged keeps its design values in CSS custom properties. They all start with `--pico-`, and the names are the same as in Pico CSS v2.1.1 by Lucas Larroche, so an old override keeps working. Change a variable and every rule that reads it follows.

Most customization needs no build step. Write the override in your own stylesheet, after the Pico link.

## Override a variable

Declare the variable on `:root` to change it for the whole page.

```css
:root {
  --pico-border-radius: 0;
  --pico-font-family: Georgia, serif;
  --pico-spacing: 0.75rem;
}
```

<Callout title="Unlayered CSS wins">
Your CSS is not inside a cascade layer, so it wins over Pico without `!important` or a heavier selector. See [Cascade layers and overriding](/docs/customization/cascade-layers).
</Callout>

### Scope a change to one element

A variable set on an element applies to that element and everything inside it.

<Example title="Variables on one element">
```html
<article style="--pico-border-radius: 1.5rem; --pico-primary-background: oklch(0.55 0.2 25); --pico-primary-border: oklch(0.55 0.2 25); --pico-primary-hover-background: oklch(0.48 0.2 25); --pico-primary-hover-border: oklch(0.48 0.2 25);">
  <h3>A rounder card with a red button</h3>
  <p>The rest of the page keeps its defaults.</p>
  <button>Primary</button>
</article>
<article>
  <h3>A regular card</h3>
  <p>Same page, no overrides.</p>
  <button>Primary</button>
</article>
```
</Example>

<Callout variant="warning" title="Variables resolve where they are declared">
`--pico-block-spacing-vertical` is declared on `:root` as `calc(var(--pico-spacing) * 1.25)`, so setting `--pico-spacing` on a single `<article>` does not change it. Set `--pico-block-spacing-vertical` and its horizontal sibling on the element instead.
</Callout>

Some elements set their own values. Headings set `--pico-font-size` and `--pico-line-height` per level (for example `h1 { --pico-font-size: 2.25rem }`), and buttons set `--pico-background-color` and `--pico-border-color` from the primary, secondary and contrast tokens. To change a heading size, write the rule on the heading, not on `:root`.

```css
h1 {
  --pico-font-size: 2.5rem;
}
```

The semantic color tokens are written once with `light-dark()`, so each holds a light and a dark value. In the tables below the first value is the light scheme and the second the dark one. A single value, or a `var()`, means both schemes use it. Hex values are approximations of the OKLCH colors in the source. How the schemes switch is explained in [Color schemes](/docs/customization/color-schemes).

The primary tokens belong to the theme. The values shown are for Azure, the default. Another theme replaces them, see [Themes](/docs/customization/themes).

## Color palette

The full OKLCH palette is not in `pico.css`. It lives in `pico.colors.css`, which defines `--pico-color-<hue>-<step>` for the 20 hues and the steps 50 to 950 in increments of 50, for example `--pico-color-azure-550`. A bare `--pico-color-azure` is the 550 step, and `--pico-color-black` and `--pico-color-white` are there too. The same file adds the `.pico-color-*` and `.pico-background-*` classes. Link it after `pico.css`.

```html
<link
  rel="stylesheet"
  href="https://cdn.jsdelivr.net/npm/@rusticstack/pico-reforged@2/css/pico.colors.min.css"
/>
```

<Example title="Palette variables and classes" css={["pico.colors"]}>
```html
<p class="pico-color-red-550">Text in red 550, from a class.</p>
<p class="pico-background-jade-600" style="padding: 0.5rem 1rem;">A jade 600 background.</p>
<p style="color: var(--pico-color-amber-450);">Amber 450, read from the variable.</p>
```
</Example>

## Extras

The opt-in extras declare their own tokens, named `--pico-<extra>-*`, for example `--pico-tabs-indicator-color` and `--pico-badge-background-color`. They are listed on the page of each extra, starting from [Extras](/docs/extras/overview).
